# Tenant account deployment

Provision host tables and reviewed Rent Ops migrations before starting the application. Set `RENT_OPS_ADMIN_EMAIL` to the exact intended staff email. Bootstrap that account with `npx tsx server/admin-bootstrap.ts`, supplying its password through protected standard input and its database URL through the deployment's secret environment. The tool requires 16–128 characters, stores the host scrypt hash, and refuses an existing email without updating credentials or role. It never prints a password. Production test seeding is forbidden.

Tenant email requires explicit `RENT_OPS_TENANT_EMAIL_ENABLED=true` after the existing HTTPS receiver has been updated and tested for `tenant.access.v1`. It uses `RENT_OPS_MAGIC_LINK_WEBHOOK_URL`, `RENT_OPS_MAGIC_LINK_WEBHOOK_SECRET`, and `RENT_OPS_PUBLIC_APP_URL`. Webhook-only configuration alone does not enable tenant email.

The receiver must authenticate the bearer secret and accept a JSON event containing `event`, `issuanceId`, `accountId`, `email`, `purpose`, `accessUrl`, and `expiresAt`. Purpose is `invitation` or `password_reset`. Deduplicate the `Idempotency-Key` per issuance; do not deduplicate all future messages for an account. Return success only when delivery responsibility has been durably accepted. Redact access URLs and credentials from receiver logs. No receiver or credentials are provisioned by this code.

Staff explicitly sends an invitation or password reset from the tenant accounts panel. Provider acceptance is displayed separately from confirmed inbox delivery. Copying a prepared link does not send it. A public reset request returns the same response for missing accounts and delivery failures. Issuing a reset preserves current credentials and sessions; consuming its one-use 30-minute token changes the password and revokes previous sessions. A failed or uncertain delivery invalidates that issuance, so a delayed email requires a fresh request. The recipient may retry or contact management.

Before launch, verify the actual HTTPS host, PostgreSQL session persistence, exact tenant binding, provider acceptance, mailbox delivery, activation, reset replay rejection, and session revocation using authorized test accounts. Local synthetic tests do not establish external receiver or production readiness.

For direct Google Workspace delivery without a separate receiver, set `RENT_OPS_TENANT_EMAIL_PROVIDER=gmail` together with the enable flag. Supply `RENT_OPS_GMAIL_FROM`, `RENT_OPS_GMAIL_CLIENT_ID`, `RENT_OPS_GMAIL_CLIENT_SECRET`, and `RENT_OPS_GMAIL_REFRESH_TOKEN` as deployment secrets from an authorized Gmail OAuth client with Gmail sending permission. The sender must be the authorized mailbox or a verified send-as identity. This adapter refreshes access through Google's documented token endpoint and sends MIME through Gmail `users.messages.send`. It neither obtains consent nor uses a signed-in browser session. No automatic retry occurs after uncertain Gmail acceptance; the token is invalidated. The same selected Gmail provider also delivers applicant resume links.

Official implementation references: https://developers.google.com/workspace/gmail/api/guides/sending and https://developers.google.com/identity/protocols/oauth2/web-server#offline.

Replit-managed Gmail is supported by the published `@replit/connectors-sdk` 0.4.3 consumer API (`ReplitConnectors.createProxyFetch("gmail")`). Set `RENT_OPS_TENANT_EMAIL_PROVIDER=replit-gmail`, `RENT_OPS_TENANT_EMAIL_ENABLED=true`, `RENT_OPS_GMAIL_FROM`, and the HTTPS public app URL. The platform manages identity and Gmail authorization through its proxy; do not add manual Google client/refresh secrets for this mode. Confirm the app runtime can list the authorized Gmail connection using the SDK before enabling delivery. The SDK source retries only an explicit HTTP 401 with refreshed platform authorization; application code does not retry uncertain delivery. Package reference: https://www.npmjs.com/package/@replit/connectors-sdk.

The Gmail provider selection serves both applicant resume and tenant invitation/reset emails. In Gmail modes startup does not require a magic-link webhook URL or secret. Application failures retain the existing withdrawal/token-revocation behavior, and no fallback transport is attempted.
