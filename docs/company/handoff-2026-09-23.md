## 7. Publishing on Replit: what to know first

- **Deployment.** `.replit` deploys as `autoscale`, running `npm run build`, then `npm run start` on port 3000 (external 80).
- **The worker is not started.** Autoscale runs only the web process, and it can scale to zero. Nothing then runs:
  - QBO sync and CDC;
  - outbox dispatch and webhook processing;
  - QBO writes;
  - daily review detection.

  Choose one of these:
  - a Reserved VM deployment that runs the web process and `npm run worker` (for example as two workflow tasks, or a supervisor);
  - a second Replit deployment for the worker against the same database;
  - Render's `type: worker` service, as `render.yaml` already describes.

  The web app works without the worker. Queued work simply waits.
- **Database.** Apply migrations 043–048 to the target database through the reviewed process before starting the new build. The app refuses to migrate at startup.
- **Secrets and environment for production:**
  - `RENT_OPS_RUNTIME_DATABASE_URL` and the existing auth/OAuth variables.
  - For webhooks: `QBO_WEBHOOK_VERIFIER_TOKEN_SANDBOX` / `QBO_WEBHOOK_VERIFIER_TOKEN_PRODUCTION`.
  - For Codex MRA tools: `RENT_OPS_MCP_MRA_CLIENT_IDS`.
  - Leave `QBO_WRITES_ENABLED` off until the read-only QuickBooks comparison is done.
  - Worker tuning is optional: `WORKER_POLL_MS`, `WORKER_BATCH_SIZE`, `WORKER_MAX_IDLE_MS`, `WORKER_SHUTDOWN_GRACE_MS`, `WORKER_ID`.
- **Demo data.** Company demo data is never seeded in production. It is seeded only by `scripts/company/demo.ts` or by tests that opt in.
