# Tenant bookkeeping sync and notification controls

QuickBooks can return a materially different body under an already mirrored SyncToken. Previously that conflict failed the entire refresh before later customers and invoices could be read. The refresh now holds the conflicting object as a scoped exception, preserves the original immutable source, continues independent objects, and marks affected coverage partial. Full replay, CDC and individual webhook reads use the same rule. An inferred deletion is restored only after the source body passes the immutable check.

Tenant bookkeeping must not send tenant communications. Explicit `RENT_OPS_TENANT_EMAIL_ENABLED=false` disables tenant invitations, password-reset emails and applicant resume emails while preserving existing password authentication and all session, storage and administrator checks. An enabled email configuration still requires its existing provider credentials and recipient policy.

No schema changes or QuickBooks writes are part of this release. Deploy the reviewed web and worker build through the existing CI gate, retain QBO write switches off, and preserve the worker's current start gate. Verify the web email switch is false, restart the web service if configuration changed, then read back account-delivery availability and health. Refresh each affected accounting company and verify current tenant customer links and invoice records. Partial coverage and held source conflicts must remain visible; queued jobs are not successful synchronization.

Tenant payment collection is intended to use QuickBooks. This sync and email-control release does not implement or verify that checkout path. Confirm the QuickBooks payment capability, correct legal entity, supported tenant-only amount and portal wiring separately before claiming payment acceptance is ready. No live charges or tenant messages are required for deployment verification.
