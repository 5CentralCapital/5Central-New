# Tenant bookkeeping sync and notification controls

QuickBooks can return a materially different body under an already mirrored SyncToken. Previously that conflict failed the entire refresh before later customers and invoices could be read. The refresh now holds the conflicting object as a scoped exception, preserves the original immutable source, continues independent objects, and marks affected coverage partial. Full replay, CDC and individual webhook reads use the same rule. An inferred deletion is restored only after the source body passes the immutable check.

Tenant bookkeeping must not send tenant communications. Explicit `RENT_OPS_TENANT_EMAIL_ENABLED=false` disables tenant invitations, password-reset emails and applicant resume emails while preserving existing password authentication and all session, storage and administrator checks. An enabled email configuration still requires its existing provider credentials and recipient policy.

`RENT_OPS_STRIPE_PAYMENT_METHODS=card` restricts newly created tenant Checkout sessions to cards. The omitted setting preserves the existing card and ACH behavior; invalid explicit values disable the provider. This avoids starting new ACH flows that require mandate or microdeposit notifications during the no-email bookkeeping setup. It does not alter existing payment events or waive ACH notification requirements.

No schema changes or QuickBooks writes are part of this release. Deploy the reviewed web and worker build through the existing CI gate, retain QBO write switches off, and preserve the worker's current start gate. Verify the web email switch is false and payment-method setting is card, restart the web service if configuration changed, then read back account-delivery availability and health. Refresh each affected accounting company and verify current tenant customer links and invoice records. Partial coverage and held source conflicts must remain visible; queued jobs are not successful synchronization.

Payment capability still depends on a verified Stripe merchant account, payout bank, legal-entity routing and current Stripe requirements. A configured secret or this release alone is not proof that payments can settle. No live charges or tenant messages are required for deployment verification.
