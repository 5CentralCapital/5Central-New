# Existing R-ops interface

Michael clarified the design direction on September 21, 2026: preserve the current manager dashboard's tables, charts, arrangement and workflows, while modernizing its appearance. The earlier rejected replacement dashboard remains outside this checkout at `/Users/michaelmcelwee/Projects/r-ops-design-work/`; it is not the implementation target.

Manager navigation is one top bar with dropdowns in this order: Dashboard, Properties, Tenants, Units, Accounting, Projects, Work Orders, Investors, Reporting and Company. The global frequently-used/recent-record sidebar and duplicate open-record strip are removed. Inner tenant/property/project record lists remain part of the original pages. `navigation.ts` maps the menus to existing routes; entries without a working feature are explicitly marked Planned and cannot mutate or masquerade as functional pages. Imports is under Accounting; no manual MRA workflow is introduced.

The visual layer follows the approved [Apple design skill](https://github.com/SudewaJay/apple-design-skill/tree/57bfab7daf8766a9a45cfc405790e749c71eda30/apple-design) at its pinned revision. `workspace-modern.css` and `dashboard-modern.css` are scoped to `.rops-modern`: system typography, restrained charcoal/gold/cream, readable opaque data panels and frosted navigation. Company → Appearance → Transparency offers System and Reduced, persisted as a device preference. OS reduced-transparency, increased-contrast and reduced-motion settings have fallbacks. No private records or credentials belong in styling fixtures or screenshots.

The current manager entry is `client/src/pages/rent-ops.tsx`, which selects `RmWorkspace` from `client/src/features/rent-ops/workspace/rm-workspace.tsx`. `?ui=classic` preserves the older workspace. `client/src/App.tsx` keeps `/tenant` and `/apply` independent.

`workspace-state.ts` owns section and record query parameters. Preserve `section`, `record`, `kind`, `tab`, `report`, `scope`, `property`, `asOf`, `status`, `search` and `tenantStatus`, plus the centralized tenant, unit and property links. Company and project identities remain scoped by `company` and `record`; `projectTab` bookmarks Overview, Scope & Budget, Schedule and Costs. Browser Back and reload restore the selected subsection. New company sections need canonical routes and aliases for existing rental bookmarks.

Reuse the existing workspace grid, record, report, banking and document patterns and the Radix controls under `client/src/components/ui`. The current palette and layout are in `workspace.css`. The separate investor portal and older investor CRM do not define the manager interface.

Projects is connected to the scoped company API and shared command service. Additional accounting, investor, work-order and company features still require their planned data/API implementation. Local browser verification uses `server/company/demo.ts` and the rental demo's synthetic repository with an explicitly guarded synthetic frontend build. `company:navigation-smoke` checks menus, keyboard/focus behavior, retained routes, project subsections, appearance preferences, responsive widths and original dashboard panels in Chromium and WebKit; `company:browser-smoke` exercises project editing and uncertain-save retry.

Reporting → Report library reads a shared authenticated discovery catalog, also exposed to Codex as `get_report_catalog`. Its 11 available rental reports reuse existing engines; the other 42 entries remain planned. Search, categories, availability filtering and browser favorites require no accounting connection or copied company data. See `reporting-contract.md` for the remaining cross-surface report-run, QBO and export requirements.
