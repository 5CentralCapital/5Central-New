# Tenant portal launch

The app includes separate tenant password accounts at `/tenant`, account grants and revocation in the admin tenant view, recurring-charge preview/post controls, and Stripe Checkout integration. Stripe remains disabled until its credentials and webhook are connected. An admin-created activation link is prepared for review; this workflow does not send invitations.

Launch requires a configured application host, reviewed host session schema, Rent Ops migrations 1–13, distinct database roles, a verified Rent Ops data import, private object storage, and the required production environment values in `render.yaml`. Startup checks those requirements and does not migrate or substitute demo data. Use the existing `RENDER_DEPLOYMENT.md` procedure for hosting. The currently inspected Neon host has only the host users table; no Rent Ops production schema or app host has been confirmed.

After deploying, confirm `/healthz` and `/readyz`, authenticate the operator, reconcile tenant/unit associations, then create an account grant for an exact person and tenancy. Review its activation link before delivering it through an authorized channel. Test activation, login, logout, password change, revocation, and cross-tenant denial against staging before inviting residents.

To connect payments, set `STRIPE_SECRET_KEY`, `STRIPE_WEBHOOK_SECRET`, and the existing `RENT_OPS_PUBLIC_APP_URL` to the HTTPS app origin (`TENANT_PORTAL_ORIGIN` is an optional override). Configure Stripe to send Checkout completion/async success/async failure/expiry, PaymentIntent success/processing/failure/cancellation, refund updates, and dispute events to `/api/tenant/payments/webhook`. Start with test credentials and verify duplicate and delayed events before selecting live credentials. A browser return does not post payment; verified provider events control payment state. Card and ACH processing, posted credits, and bank settlement are separate states.

Run `npm run check`, `npm run test:rent-ops`, and `npm run build` for local validation. For isolated browser QA after a standard build, run `NODE_ENV=development npx tsx scripts/tenant-local-qa.ts` and open `http://127.0.0.1:4176/tenant`. This harness uses only in-memory PGlite and synthetic residents, binds to loopback, and has no payment provider. Its synthetic login is `resident@example.test` with password `LocalQA-Only-2026`. Stop the process to discard all QA accounts and sessions.
