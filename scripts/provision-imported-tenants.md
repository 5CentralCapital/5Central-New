# Private tenant provisioning operator

Run on the existing web runtime after the frozen schema025 importer commits and both import audits pass, a populated backup is verified, and additive schema026 is separately approved/applied. Verify a populated schema026 backup and publish matching reviewed code before provisioning. This script never applies migrations, sends email, or creates activation tokens.

Provide private paths through `RENT_OPS_LEASE_MANIFEST`, `RENT_OPS_PROVISION_ROSTER`, and `RENT_OPS_LEASE_ARCHIVE`. The archive is extracted into a temporary directory and deleted afterward. Keep its manifest and roster private; never add them to the repository or a public asset bundle.

`npx tsx scripts/provision-imported-tenants.ts --verify-files` verifies every eligible PDF offline without opening a database connection.

`npx tsx scripts/provision-imported-tenants.ts` performs production-ID source resolution and a no-write preflight using the existing `RENT_OPS_RUNTIME_DATABASE_URL`. It requires the exact reviewed schema001–026 version/checksum chain and `RENT_OPS_PROVISION_CROSSWALK`; it does not derive IDs from an import key. Export that private production identity crosswalk in a separate read-only source-role process with `npx tsx scripts/export-provisioning-crosswalk.ts`, using ephemeral importer credentials in `RENT_OPS_SOURCE_IDENTITY_DATABASE_URL` and the absolute private output path `RENT_OPS_PROVISION_CROSSWALK`. Provide the audited committed production receipt path as `RENT_OPS_PROVISION_IMPORT_RECEIPT` to both processes. The exporter binds the private crosswalk to a credential-free database endpoint fingerprint and exact receipt SHA256; the runtime verifies both before resolving identities. The exporter uses a read-only transaction and writes a new 0600 file; it emits no row identities. Do not reuse a rehearsal export. The runtime never queries restricted source tables or receives source-role credentials. Missing/ambiguous crosswalks stop execution. Use the existing secure runtime credential mechanism; never put a database URL in arguments or files.

After root authorization, set `RENT_OPS_PROVISION_APPROVAL=two-imports-audited-schema26-approved` and `RENT_OPS_PROVISION_MANAGER_SUBJECT` to the verified manager actor, then run with `--apply`. Use the existing web-role storage configuration and runtime identity. Do not provide importer credentials or broaden grants.

All source bindings and file bytes are checked before writes. Existing accounts are preserved, including activated credentials. Missing primary email holds only account creation; independently reviewed lease PDFs can still bind to the exact tenancy. Future accounts may be created only when their exact primary email and source-backed canonical future tenancy resolve; otherwise an explicit unresolved-tenancy hold is reported; no missing lease is fabricated. The nine lease review holds remain excluded. Uploads use manual verified-file classification, not a new assertion of execution or signature status. Every saved file is reopened and hashed. Retry verifies existing exact files rather than duplicating them.

Output contains counts only, with zero emails and activation tokens. A failure may occur after partial progress: inspect the private account/document state and rerun the preflight before retrying. The script never revokes, rotates, resets, or deletes accounts.

Both crosswalk export and provisioning reject an incomplete, changed, duplicated, older, or newer schema chain. The pinned schema026 checksum is `f6a2872ffc21150351d441759886fd778c076981e96435847a7f82f32dea0a96`; full ordered-chain digest is `a6be5d43fd6db0e46c56fde4acd2fbd3f31ece5608c3edd5ccf600ceab8a35ad`. Changing migration code requires another explicit review; this is not a >=25 compatibility bypass. The original schema025 committed/postcommit-audited receipt remains the exact receipt-byte hash bound into the crosswalk; upgrading the additive schema does not replace that import evidence. The approval phrase is an operator gate, not proof that audits or backups happened.
